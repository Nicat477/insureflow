# InsureFlow account mode — phase 1

Local testing only until all security and email flows are verified. Fictional insurance records only; do not enter real customer, health, or financial information. Use an age-eligible service account and no paid upgrades without appropriate authorization.

1. Stop frontend/backend. Make sure current main is clean and contains PostgreSQL migration. Run `npm run db:backup` in backend. Create feature/authentication branch. Run installer dry-run, then actual installer from repository root. Install frontend SDK: `pnpm add @supabase/supabase-js@2 --save-exact`. Run frontend build and backend tests.
2. Supabase Authentication: enable email signup and email confirmation, minimum password length 12. Disable anonymous sign-in. Set Site URL to https://insureflow-demo.onrender.com/ and allowed redirect URLs exactly `http://localhost:5173/` and `https://insureflow-demo.onrender.com/`. Default SMTP only sends to authorized project team emails; configure eligible custom SMTP and test confirmation/recovery before public signup. Do not disable confirmation merely to bypass the SMTP restriction. Use publishable key (not secret or service role key).
3. Append to existing backend/.env (do not replace PostgreSQL vars):
```
AUTH_MODE=supabase
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
```
4. `npm run auth:init` creates a new private account_workspace table; the legacy row is retained. Start backend and frontend. Create a verified owner account via Supabase Authentication Users (or normal signup + confirmation). To import your legacy snapshot into that account, before opening its workspace, stop backend, copy the verified user UUID from Supabase Users, then `npm run auth:import-legacy -- USER_UUID`. It refuses to overwrite an existing account workspace. Do not import into another person's account. The older JSONB backup command currently exports only the legacy workspace, not the new account table.
5. Start backend/frontend. Expect /api/health auth:supabase; unauthenticated GET and POST /api/customers must return 401. Test login/logout, email verification and recovery; compare two verified test accounts: A creates a fictional customer and CRM/payment records, B must not see or modify A's records; reload A on a second browser. Test the entire insurance flow and mobile themes. Check cache is cleared on account switching. Do not deploy until these pass.
6. Later deploy: set AUTH_MODE=supabase, SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY in Render alongside unchanged PostgreSQL SSL settings, keep current live deployment until tests pass. Existing shared demo gate is bypassed only in explicit account mode, and all business API endpoints require a server-verified identity. Legacy mode remains for existing tests; do not accidentally revert live auth configuration. Public landing/guest, admin UI, profile editing, password visibility, abuse rate limits for business APIs and account backups remain future work. SDK session tokens live in browser storage; a hardened production system needs a security review (XSS controls, rate limits, session strategy, audit and privacy design). Supabase default email delivery is limited. No production-readiness claim.
